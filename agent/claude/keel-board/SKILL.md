# Keel Board: the directory is the board — move files, never edit `BOARD.md`

A person working with you has the Keel Board plugin in Obsidian, showing a folder of markdown
cards as a kanban board and moving the file when they drag a card. Everything it shows comes
from three things you also write: the `board.json` manifest, the card files, and the
directories they sit in. `BOARD.md` is generated from those; it is output, not input.

## The shape

```
board/
  board.json              # id, title, prefix, next, provider, ordered columns
  backlog/                # a column directory
  wip/
  done/2026/
  BOARD.md                # generated; marked; never hand-edited
```

A board is any directory with a `board.json`. Without one, the default three columns are
`backlog/`, `wip/` and `done/{year}/`, mapping to `todo`, `in_progress` and `done`. The
manifest's `columns` are ordered and each maps a directory to one of those three states.

A card is `<PREFIX>-<N>-<slug>.md` inside a column directory, with frontmatter:

```yaml
---
id: KB-3
title: "Add card with minted id, regenerate BOARD.md"
state: todo
column: backlog
type: feature
created: 2026-09-07
updated: 2026-09-07
links: [KQ-1]
---
```

Quote `title:` when it contains a colon, or the frontmatter is not valid YAML and every reader
loses the card's title.

## Moving a card is moving a file

To change a card's state, **move the file** into the other column's directory, then update
`column:`, `state:` and `updated:` to match. Three fields, nothing else. Do not rewrite the
body, do not renumber, do not touch `created:`.

The directory is the truth. If `column:` in the frontmatter and the directory disagree, the
directory wins and the frontmatter is stale — fix the frontmatter, never "fix" it by moving the
file somewhere the person did not put it.

## Never edit `BOARD.md`

`BOARD.md` carries the line `<!-- generated by pangolin-board; do not edit -->`. It is
regenerated from the manifest and the cards, by this plugin's *Regenerate BOARD.md* command or
by pangolin-board's CLI — the two produce identical bytes.

- Never hand-write a row into it, never fix a stale row by editing it, never reorder it.
- After you add, move or retitle a card, regenerate it — or leave it and say so; it is derived
  state and a person can regenerate it in one command.
- A `BOARD.md` **without** the marker is somebody's hand-maintained file. Do not overwrite it.
  Say it is hand-maintained and let the person choose.

## Minting an id

`next` in `board.json` is the only counter, and every writer shares it: this plugin's
*Add card*, Keel Keys' *New card*, pangolin-board's CLI, and you. Read the manifest fresh,
take `next`, write `next + 1` back, **then** create the file. Without a manifest, mint from the
highest existing number plus one and do not create a manifest.

Never reuse a number, never renumber to close a gap. A leaked number costs nothing; a reused
one breaks every reference.

## Providers

`provider: pangolin-board`, or no manifest at all, means the directory is the source of truth
and you may write. `provider: jira` means the board is a mirror of another tracker: it is
**read-only**. Do not create, move or edit cards there; changes go to the tracker, and come
back through keel, not through the vault.

## Two card shapes

Cards written before the format migration carry their metadata as bold header lines
(`**Status:** todo · **Updated:** …`) instead of frontmatter. **Read** both shapes. **Write**
only frontmatter. If you are editing an old card anyway, converting it is fine; converting a
whole board is a migration and belongs to pangolin-board's CLI, not to an ad-hoc loop.

## Do not

- Do not edit `BOARD.md`, or any other generated file.
- Do not change a card's state without moving its file, or move its file without updating
  `column`, `state` and `updated`.
- Do not write to a `jira` board.
- Do not invent a prefix or a column; both come from `board.json`.
- Do not leave `title:` unquoted when it contains a colon.
